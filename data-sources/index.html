MARKET DATA

Know what the chart is actually showing.

Tickrift distinguishes provider-linked market data from generated simulation prices.

The data badge beside every instrument is the source of truth inside the interface. If a provider request fails, Tickrift falls back to SIMULATED rather than pretending generated prices are live.

Three data states

MARKETProvider-linked data

The current price and chart history came from the configured market-data provider.

DELAYEDProvider-linked, delayed

The data came from a provider but is explicitly marked delayed according to the configured data entitlement.

SIMULATEDGenerated practice prices

No provider data is currently being used for that instrument. The simulator generates movement for practice only.

NO HIDDEN FEEDStatus stays visible

The interface never labels generated prices as live market data.

Production market-data bridge

The production package includes a same-origin serverless bridge at /api/market. It keeps the provider key out of public JavaScript and exposes only the price and candle fields Tickrift needs.

The included bridge is written for Twelve Data. Before public commercial display, the site owner must use a provider plan and any exchange entitlements that permit the intended display and redistribution. A working API key is deliberately not shipped in the repository.

Why a simulator can differ from a real trade

A displayed chart does not reproduce order-book depth, queue position, partial fills, every fee, venue routing, halts, corporate actions or all latency. Tickrift applies simplified simulated slippage and fees so an order is not treated as a guaranteed exact fill.
